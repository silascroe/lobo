# Status

## Built

1. **Model client** — `lobo/model.py`. Sends a conversation to any OpenAI-compatible chat endpoint and returns the reply, token counts, and the model's separate reasoning text if it has one. Default is `deepseek-flash` (DeepSeek-V4.1-Flash, thinking mode on by default, default effort; `temperature` is ignored in thinking mode). Standard library only.

2. **Memory** — `lobo/memory.py`. Two layers, after Hermes/OpenClaw: `home/notes.md` (curated, capped at 2,400 chars, shown to the model every wake) and `home/memory.db` (append-only SQLite event log; recent events shown, the rest searchable).

3. **Heartbeat** — `lobo/heartbeat.py`. Wake, show the model its memory, save its thought / notes rewrite / chosen next wake (clamped 10 min to 24 h), sleep. Replies use DeepSeek JSON mode (`json_mode` option added to `model.py`). Failed beats are logged and retried in 30 min; a final reply missing `next_wake_minutes` is logged as an error (with the raw reply) before defaulting to 30. Each step's private reasoning is logged as a `reasoning` event (header only on Lobo's page). Runs as a watchable terminal loop; `--once` for a single beat, `--home` for a separate Lobo.

4. **Tools + recall** — `lobo/tools.py`. A wake-up can now take several steps: Lobo replies with a tool request in JSON, the heartbeat runs it and sends back the result, up to 5 calls per wake. First tool is `recall`, a read-only search of Lobo's full event log (skips past tool results so searches don't echo each other). Plain-JSON protocol, not native function calling, so every step is readable in the log.

5. **Workspace file tools** — `list_files`, `read_file`, `write_file` in `tools.py`, confined to `home/workspace/`. Every path goes through `_resolve()`: rejects colons (drives, `C:foo`, alternate data streams), absolute and UNC paths, null bytes, and Windows reserved names, then resolves the path (collapsing `..`, following symlinks/junctions) and refuses anything not under the workspace. Limits: 8,000 chars per read shown, 50,000 per write, 10 MB total. Tested against 99 escape attempts including a planted junction to an outside folder (symlinks untested: they need Developer Mode on this machine; resolve() follows them the same way). Every write's full content is kept in the log's `tool` event.

6. **Unattended running** — `scripts/install-task.ps1` registers a Windows scheduled task ("Lobo heartbeat") that starts the heartbeat hidden (`pythonw`) at login, no admin needed. Supporting edits to `heartbeat.py`: an OS-level lock file so only one heartbeat runs per home (a second exits; the lock vanishes with a crashed process); `--log` sends output and crash tracebacks to `home/heartbeat.log`; sleeping is done in 30-second chunks against the wall clock, so if the PC sleeps, Lobo wakes as soon as it resumes past its chosen time; `--scheduled` makes the start event read "started automatically by Windows Task Scheduler". Tested the lock across real processes (including a killed holder), the clock-jump sleep with a fake clock, and the log redirect.

7. **Automatic backup** — `lobo/backup.py` + `scripts/install-backup-task.ps1` (task "Lobo backup", every 6 hours, hidden, log in `home/backup.log`). Commits whatever changed in `home/` and pushes it, with three safeguards: it only runs between wake-ups (last event is `sleep`/`stopped`, or the log has been quiet 10+ minutes, and no SQLite journal file exists); it opens the staged copy of `memory.db` and runs an integrity check, refusing to push a bad one; and it refuses outright unless `home/.git` exists, since otherwise Git would walk up and commit the code repo. A skipped run is not an error (the next one catches up); an unreadable database or failed push exits nonzero. Unpushed commits are retried on the next run. Tested against a throwaway repo with a local remote (21 checks: mid-wake skip, stale wake, journal present, corrupt database, wrong-repo refusal, push failure and retry), then run for real.

8. **Day files** — `lobo/days.py`. Rewrites the whole event log as `home/days/YYYY-MM-DD.md` (local time, one section per wake: thoughts and sleeps in full, reasoning / tool results / notes rewrites folded into click-to-open sections) plus `days/README.md`, an index with wake and token counts per day. A view for the owner, not memory: regenerated from scratch each time, so it can't drift from the log, and it sits outside `workspace/` so Lobo never sees it. The backup regenerates it before every commit, so it shows up on GitHub (readable on a phone). Lobo's earliest notes rewrites predate full-text logging and show as "full text wasn't kept".

9. **Alarms** — `lobo/alarms.py`, plus `set_alarm` / `cancel_alarm` tools. Lobo can leave a message for a future wake (10 min to 30 days ahead, up to 20 pending, 500 chars each). They're stored in an `alarms` table in memory.db, so restarts and backups keep them. Supporting edits: the heartbeat sleeps until whichever comes first, the wake Lobo chose or its earliest alarm; on waking, due or overdue alarms "ring" as `alarm` events (so they show up in the recent log) and are marked fired so they never ring twice; pending alarms are listed on Lobo's page under "Your alarms"; day files render rung alarms. Tested with a scripted fake model (27 checks: set, list, ring once, overdue after restart, every refusal, survives reopen).

10. **Inbox** — `lobo/inbox.py`, plus the `message_owner` tool. Letters, not tickets: an owner message waits in a `messages` table in memory.db and is delivered at Lobo's next wake as a `message` event (so it's in the recent log and recallable). `--now` makes it a knock: the sleeping heartbeat checks for one between its 30-second sleep chunks and wakes early. Lobo can write back with `message_owner`; its messages are logged as `message` events too. Lobo's prompt gained one sentence: "Your owner may sometimes send you a message; it appears in your log." Day files render both directions as quotes. Owner messages are the owner's words verbatim; an agent relaying for the owner never writes to Lobo in the owner's name on its own. Tested with a fake model and a second process sending (25 checks: letter vs knock, single delivery, cross-process knock interrupts sleep, read/new markers, refusals, recall, day files).

## The live Lobo

Born 2026-10-17 in `home/`, running on DeepSeek Flash. So far it set itself a "slow journal" practice, theorized its wake interval was being "compressed" (it was really owner restarts), corrected that once restarts were logged, used recall unprompted to investigate a said-240/slept-30 mismatch, and wrote itself a rule to verify claims against its log. Read its history with `python -m lobo.memory search <word>` or its `notes.md`.

`home/` is its own Git repo, pushed to the private `silascroe/firstborn` (the code repo ignores it), backed up automatically (see piece 7). `home/.git` is outside `workspace/`, so Lobo's tools can't reach it. To restore on a new machine: clone firstborn into `home/`, reinstall Python, set the key, run both install scripts.

Since 2026-10-17 it runs under Task Scheduler rather than inside a dev session, so it keeps living with the app closed. Only logging out or shutting down stops it; it restarts (and wakes immediately) at next login.

## Known gaps

- The task runs only while you are logged in. Surviving a reboot with nobody logged in would need "run whether logged on or not", which stores your Windows password with the task; not worth it for now.
- A PC that sleeps overnight means Lobo wakes late, not on time. It isn't told why beyond the timestamps.
- Restarting the heartbeat wakes Lobo immediately, ignoring the wake time it chose. Deliberately left as is for now: each start logs a `start` event ("restarted by the owner" / "woken manually by the owner") and Lobo is told nothing more. Early on it theorized its interval was being "compressed"; watching whether it connects that to the start events is part of the experiment.
